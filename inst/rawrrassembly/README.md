# Setup

All commands in this document are executed live at render time against the
compiled `rawrr.exe` binary and the `sample.raw` demo file. Their **absolute
paths** are defined once here and exported as environment variables, so every
code chunk below uses the exact same files.

By default the assembly installed by `rawrr::buildRawrrExe()` is used; set the
environment variable `RAWEXE` before rendering to document another build.

```{r setup}
#| echo: true
RAWEXE  <- Sys.getenv("RAWEXE", rawrr:::.rawrrAssembly())
RAWFILE <- rawrr::sampleFilePath()

Sys.setenv(RAWEXE  = RAWEXE)
Sys.setenv(RAWFILE = RAWFILE)

stopifnot(file.exists(RAWEXE), file.exists(RAWFILE))

# Run all later code chunks (bash included) in a scratch dir so that the
# temp input/output files they create do not clutter the source tree.
workdir <- tempfile("rawrrdoc-")
dir.create(workdir)
knitr::opts_knit$set(root.dir = workdir)

cat("rawrr.exe:", RAWEXE, "\n")
cat("sample.raw:", RAWFILE, "\n")
cat("scratch dir:", workdir, "\n")
```

# Usage

```
rawrr.exe <raw file> <option> [<arguments>]
rawrr.exe help [<option> | --markdown]
rawrr.exe version
```

- The **raw file path** is always the first argument.
- The **option** (mode) is always the second argument; it selects the operation.
- Arguments after the option are mode-specific, see the table below.
- The R package always passes the same base layout `<rawfile> <mode> <inputfile> <outputfile>` for the R-code generating modes and fills `<inputfile>` / `<outputfile>` with temp files under `tempdir()`.

## Options

The following table is **generated by the binary itself** (`rawrr.exe help
--markdown`) from the command table in `rawrr.cs`, so it always matches the
build used to render this document. `[ ]` marks optional arguments.

```{bash options}
#| output: asis
#| echo: false
"$RAWEXE" help --markdown
```

# Help & version (no raw file required)

| Token | Action |
|-------|--------|
| `help`, `--help`, `-h`, `h`, `/h` | Print usage and the list of options, then exit 0. |
| `help <option>` | Print the arguments, description, and output of one option, then exit 0. |
| `help --markdown` | Print the option table as markdown (used above), then exit 0. |
| `version`, `--version`, `-v`, `-V`, `/v` | Print the assembly version, then exit 0. |

# Modes

## `index` — scan index as CSV on stdout

```{bash index}
"$RAWEXE" "$RAWFILE" index | head -4
```

::: {.callout-note title="Full output"}
The complete index is `575` lines (a header line plus one line per scan);
`sample.raw` holds `574` scans.
:::

## `headerR` — metadata as R code

```{bash headerR}
"$RAWEXE" "$RAWFILE" headerR /dev/null header.R
head -6 header.R
```

## `filter` — scan numbers matching a filter, one per line

```{bash filter}
"$RAWEXE" "$RAWFILE" filter ms 10 filter.txt
head -8 filter.txt
```

If the filter is invalid, a message is written to stderr and the process exits
with status `1`.

## `getFilters` — all scan filters of the raw file

```{bash getfilters}
"$RAWEXE" "$RAWFILE" getFilters
```

## `isValidFilter` — check whether an argument is a valid filter

```{bash isvalidfilter}
"$RAWEXE" "$RAWFILE" isValidFilter 'FTMS + c NSI Full ms [350.0000-1800.0000]'
```

## `scans` — full spectra for requested scan numbers as R code

```{bash scans}
printf '3\n4\n5\n' > scanfile.txt
"$RAWEXE" "$RAWFILE" scans scanfile.txt scans.R
sed -n '1,10p' scans.R
```

## `barebone` — reduced spectra as R code

```{bash barebone}
printf '3\n4\n5\n' > scanfile.txt
"$RAWEXE" "$RAWFILE" barebone scanfile.txt barebone.R
sed -n '1,13p' barebone.R
```

## `chromatogram` — BPC and TIC as CSV

```{bash chromatogram}
"$RAWEXE" "$RAWFILE" chromatogram ms chrom.csv
head -6 chrom.csv
```

## `xic` — extracted-ion chromatograms within a mass tolerance as R code

```{bash xic}
printf '669.8381\n726.8357\n' > massfile.txt
"$RAWEXE" "$RAWFILE" xic 10 ms massfile.txt xic.R
sed -n '1,11p' xic.R
```

## `trailer` — trailer labels, and values for one label

```{bash trailer-labels}
"$RAWEXE" "$RAWFILE" trailer | head -12
```

The three-argument form prints the per-scan values of one label (one per line).

```{bash trailer-values}
"$RAWEXE" "$RAWFILE" trailer 'Ion Injection Time (ms):' | head -8
"$RAWEXE" "$RAWFILE" trailer 'Master Index:' | head -8
```

## `devices` — instruments (devices) stored in the raw file

A raw file stores the data of each device of an LC-MS system (mass
spectrometer, LC pump, autosampler, UV detector, ...) as a separate
*instrument*. The device index is 1-based within each device type.
`sample.raw` only contains the mass spectrometer.

```{bash devices}
"$RAWEXE" "$RAWFILE" devices
```

## `statusLog` — status log labels, and the trend of one label

Each device records a status log, a time series of instrument readings.
LC pumps (usually device type `Other`) log, e.g., their pressure here.
Without a position, the plottable (numeric) labels and their positions are
listed:

```{bash statuslog-labels}
"$RAWEXE" "$RAWFILE" statusLog MS 1 | head -8
```

With a position, the trend of that label is printed (retention time in
minutes; value):

```{bash statuslog-values}
"$RAWEXE" "$RAWFILE" statusLog MS 1 7 | head -6
```

In R, use `rawrr::readDevices()`, `rawrr::readStatusLog()`, and
`rawrr::readPressureProfile()`.

# Exit / error behavior

- No argument → prints `No RAW file specified!` on stdout and exits 0 (health
  check used by `rawrr:::.isAssemblyWorking()`).
- Unknown option → prints `Option '...' is not defined.` and the option list on
  stdout and exits 1 (the R package uses this text to detect outdated
  assemblies).
- Too few arguments for an option → usage line on stderr, exit 1.
- Raw file cannot be opened, is still being acquired, or the RawFileReader
  library fails → message on stderr, exit 1.
- Invalid filter (`filter`, `chromatogram`), missing mass file (`xic`),
  unknown device or status log (`statusLog`) → message on stderr, exit 1.
- Otherwise the exit status is 0.

# Notes for the R wrapper

The package's shared helper `.rawrrSystem2Source()` always hands
`<rawfile> <mode> <tfi> <tfo>`, where `tfi` is a temp file holding `input`
(scan numbers or masses, one per line) and `tfo` is the temp R-script file that
is `source()`d back on exit. Beware: it stages the `version` subcommand through
`.getRawrrAssemblyVersion()` and dispatches all other modes through this one
pathway or direct `system2()`.

# Maintaining this document

The options are defined once, in the `Commands` table of `Program` in
`rawrr.cs`; the help output and the option table above are generated from it.
When adding an option, add a `## \`option\`` section with an example to the
*Modes* chapter. `tests/testthat/test-assembly-doc.R` fails if an option of the
installed assembly has no such section.
